# Review tracking

Full-codebase review, 2026-10-10. Every finding was checked against the real
upstream contract (CrowdSec LAPI source, Cloudflare API docs, upstream bouncer
configs), not against our own mocks, because the mocks had been written from
the client's assumptions. That is how several breaking bugs passed CI.

Severity: **Critical** = core function broken against real systems, or a
production site can go down. **High** = a feature is broken or a security
boundary has a gap. **Medium** = wrong behaviour in a narrower case, or
defense in depth. **Low** = hygiene.

## Accepted risks (decided)

- DNS rebinding between the guard's lookup and the connect is still possible. Webhook and probe destinations are admin/operator configuration.
- Webhooks may go to private LAN addresses (ntfy/Gotify). Probes may go to loopback and LAN (local proxies).
- The 2FA throttle is per IP, so users behind one shared NAT can lock each other out for up to 10 minutes.
- The API rate limiter is in memory and resets on restart (single process).
- Stored Cloudflare tokens and channel secrets are encrypted with a key derived from `BETTER_AUTH_SECRET`. Rotating that secret means re-entering them.
- Any role can change the shared inbox read state.
- The CSP has no `script-src` because `app.html` runs an inline theme bootstrap.

## Backlog (deferred on purpose)

- A hash-based `script-src` CSP, via SvelteKit CSP config.
- Jobs drain inside the worker tick, so a long agent job delays sync and notification delivery. Split the loops.
- NAT64 (`64:ff9b::/96`) in the SSRF guard.
- Escape `LIKE` wildcards in list filters.
